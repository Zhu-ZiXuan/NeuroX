# Markdown style

Use [GitHub Flavored Markdown](https://github.github.com/gfm/) and the [Google documentation style guide](https://developers.google.com/style/), with these project conventions.

## Structure

- Use sentence case for headings and navigation labels.
- Give fenced code blocks a language. Keep one paragraph or list item per source line; retain line breaks required by Markdown structure.
- Use relative `.md` links for source documents and heading fragments for sections. Link to the information needed at that point; avoid repeating the same destination in adjacent paragraphs.
- Keep the root README useful on its own. Create directory indexes only where readers need a choice of destinations.
- Omit empty headings, generic `TODO` sections, and easy-to-stale inventory counts. Keep specific unresolved scientific questions visible until evidence resolves them.

## Presentation

Use numbered lists for ordered procedures, tables for comparisons, and prose for connected reasoning. Examples should resolve an actual usage question. Verify runnable examples when their interfaces change; explanatory pseudocode remains illustrative.

Use LaTeX for mathematical expressions and follow [notation and units](notation_conventions.md). Use Mermaid for small structural diagrams and vector assets for precise circuit schematics. Do not insert placeholder diagrams merely to fill a template.
