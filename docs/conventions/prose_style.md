# Prose style

Write concise English for the intended reader, following the [Google documentation style guide](https://developers.google.com/style/).

- Lead with the useful fact or action. Explain reasons only when they affect use, interpretation, or extension.
- Match prerequisites to the page: quickstarts introduce NeuroX concepts; scientific references define model-specific notation and assumptions.
- Give each paragraph one subject. Remove repeated conclusions, ownership slogans, and explanations that merely restate a name or signature.
- Distinguish modeled, assumed, calibrated, and measured quantities. A configuration value is not evidence of physical accuracy.
- Keep terminology consistent with the [glossary](glossary.md). Expand unfamiliar acronyms on first use.
- Use ordinary words where possible; avoid replacing “configure” or “calibrate” with “seat.”

Symbols and units are defined in [notation](notation_conventions.md); source-text characters follow [code style](code_style.md#characters-and-notation). API format and pseudocode conventions are defined in [code style](code_style.md#docstrings).
