# Profiler

`NeuroxProfiler` (`common/profiler.py`) is the context manager that collects the PPA side channel: during its `with` block it captures the per-call dynamic-energy events that leaves emit, walks the module tree for the hosts that report static area / leakage, and aggregates both into a `ProfilerReport`. It is the collector half of the mechanism — the per-module emitter is the profile mixin — and how each PPA quantity is physically computed is a per-subsystem cost model. Duration is not collected: every module states its own, so it is asked rather than recorded.

## Design decisions

- **A tensor axis is physically a space axis or a time axis, and only that classification carries PPA meaning.** A **space** axis is spread across several fabricated instances that execute at once; a **time** axis is executed sequentially inside one instance. Software classifies the same dimension independently, as a parallel axis or a serial (Python-loop) one. The physical class is what decides whether $N$ positions cost $N$ durations or one, so it is the only one a cost model reads. Both physical classes are software-parallel here; the sole software-serial axis in the library is the solver's chunk loop, which bounds peak VRAM and describes no circuit.
- **The physical classification is declared, never inferred.** A broadcast shape, a size-1 slot and a loop trip count are software-level evidence, and none of them answers the physical question. The layer that introduces an axis is therefore the layer that states its class — in the config field that fixes its extent, and in the duration formula that counts it — while a module handed an axis from above classifies nothing. Reading a physical verdict off a runtime layout is a category error, not a shortcut.
- **A module's duration is its own to state, and covers only the time axes it introduces.** Composition is bottom-up: a composite whose own circuit model already spans its children's windows multiplies its own time axes rather than summing children, the same ownership principle `is_profile_target = False` expresses for area.
- **Duration is declared per family, not universally.** `latency__ns` is abstract on four family bases — `Iadc`, `DiffVadc`, `CimMacro` and `CimUnit` — and concrete on `CimEngine`; nothing else has the method, and `ModuleBase` declares none. Each family takes the arguments its own question needs and no more: an ADC the executed bit count, a macro the ADC resolution, a unit the input shape plus that resolution, the engine the plane count its unit computed. A shared parameter object is deliberately not used, because it would make every family carry the union of the others' questions. There is no default implementation and no universal formula: one work multiplies its bit count, another is affine in it, and a summing default would be silently wrong for any module that loops. A module that introduces no time axis of its own carries no duration method at all, so its area, leakage and duration all say the same thing.
- **Leakage power is a given circuit figure; the instance count is what is computed.** A per-instance leakage power is a design number a config declares, and nothing derives it. What a module computes is how many circuit instances its design parameters imply — a lane count from a column count and a sharing factor, say — and its leakage total follows as the declared per-instance power times that count. Area follows the same direction.
- **Dynamic energy arrives on a side channel, not in return values.** Every numerical return in NeuroX is the analog / digital result; the switching energy reaches the profiler through the emission entry instead of being threaded back through call signatures. Rationale: the hot-path tensor pipeline stays narrow and a leaf deep in a composite can attribute its own cost without every intermediate function growing a PPA out-parameter. The cost is a discoverability one — emission sites are invisible from a function's signature.
- **No active profiler means no pure energy work.** A leaf queries the thread-local profiler before evaluating formulas used only for dynamic-energy reporting. With no active context it skips those formulas entirely. When a profiler is active, collection is mandatory; `NeuroxProfiler` has no enable switch.
- **Energy is collected as a tensor, not a Python float.** It is genuinely per-element — per-unit-operation, per-instance switching energy the profiler reduces — and staying on device until finalization lets every event share one batched device→host sync instead of forcing a per-event `.item()` that would stall the pipeline on a GPU sync for one float.
- **`leading_rank` is a property of the measurement and a reporting-resolution knob.** Only the measurement site can say how many leading dims its caller owns, so the rank is a construction argument of the context, and the collector alone applies it: it keeps that many leading dims of a payload and sums every axis past them. Nothing physical rides on the number — summation is summation, and every scalar view reduces an event to a scalar anyway — so a rank that misjudges the caller block changes no total, only how finely the per-unit-operation view resolves.
- **Nothing on the emission path computes but the reduction.** `_record_dynamic_energy` takes a tensor and an optional channel: the mixin hands it to the active collector untouched and the collector only reduces it, so turning a per-op constant into a tensor is the emitting subclass's own arithmetic. A constant-per-element bill costs nothing extra all the same: the emitter expands a 0-dim constant onto the billed layout, which holds no storage, and reducing over its stride-0 axes allocates only `[*caller_leading]` instead of a multi-million-element payload. The constant also fixes the event dtype, since a billed layout is typically an integer code or a reduced-precision signal.
- **One batched sync, deferred to context exit.** During the `with` block each emission stashes its already-reduced payload on the recording device; finalization stacks one scalar per event and does a single batched device→host transfer. Total host-sync cost is independent of event count. Rationale: a model with $10^5$ emitting calls would otherwise pay $10^5$ device syncs.
- **No static-walk cache.** `collect_static` re-walks the graph on every report; the per-module area / leakage properties it reads are plain arithmetic on init-fixed data, so a report is safe to take repeatedly.
- **Static collection keys on the profile-target flag.** Every module is a `ProfileMixin` host carrying the `area__um2` / `leakage__uW` surface, so being a host does not imply owning reportable silicon: the walk keys on `is_profile_target` and reads the two properties from the hosts that declare it true. That selects exactly the modules accounting for themselves — a composite reports only its own overhead while its children self-report, and a host the walk skips is also barred from emitting a dynamic event of its own, so nothing is double-counted.
- **A composite billing more than one branch per op names them with a `channel`, not separate emitters.** `_record_dynamic_energy` takes an optional `channel: str | None` kwarg; the profiler keys the event by `(module, channel)` instead of by module alone. A report names a channelled row `"<module dotted name>.<channel>"`; `channel=None` (the default) is byte-identical to a plain un-channelled event and groups under the bare module name. This lets one physical module emit several independently-billed branches (e.g. a clamp-side branch alongside an array-side branch) without inventing a child module purely to carry a name.
- **A name needs a root, so the per-name breakdown is the report's, not the profiler's.** An emitter cannot name itself: `nn.Module` records a child as a key in its parent's `_modules` dict and leaves the child object untouched, so there is no back-link and no stored path — a dotted name exists only as the prefix a traversal threads down from a root. Nor is placement fixed at construction, since a tree is re-parented after assembly — a probe swapped in for the block it stands in for, a `nn.Linear` replaced by its quantized twin — so the earliest a name is knowable is after assembly, from a root. The profiler is a context, not a tree: it captures whatever emits on its thread and structurally has no root to name an emitter against. The aggregations that need no root — the totals, and the by-type grouping — are therefore the profiler's, while `energy_by_name` belongs to `ProfilerReport`, which `report(model)` builds against the root it is handed. The same events reported against a different root read out under different names, and the root itself is named `""`, as its own traversal names it.
- **An unnameable event is labelled, not dropped.** Events are the context's, not the model's, so an emitter the reported root does not reach still contributes to the totals. It is labelled `<unrooted>.<ModuleType>` — a module with no tree has no name, and its type is the only thing left that identifies it — which keeps it visible in the grouped sums instead of vanishing or merging into a real name. The angle brackets cannot occur in an attribute path, so the label never collides with a traversal name. Reaching this label usually means an emitter is held in a plain container instead of bound as a child, which hides it from the walk.

## Contracts & invariants

- **Record inside the `with`, read after it.** Inside the block each emission appends its reduced device tensor to a pending list; reading any aggregation or calling `report()` there sees the reset zeros, not partial state. `__exit__` clears the active-profiler slot, then finalizes **only on clean exit** — an exception leaves the partial state alone and avoids a stray sync that could mask the original error. After exit every accessor is a pure CPU field read.
- **Active profiler is thread-scoped.** The active profiler is held per thread; a leaf's emission is a no-op when no profiler is active on the calling thread. Emission and the enclosing `with` block must run on the same thread.
- **The profiler is the single source of aggregation across events and across the folded axes.** Each dynamic contribution reaches the collector as its own event, and the collector alone sums across events and across every axis past the caller's leading dims; it never re-sums a total, so the per-op totals are authoritative here and nowhere else. The emitter side upholds the complement — the emit-once contract: each logical operation emits at most one energy event per channel, and a composite emits only its own per-op overhead, never a sum of its children's, because every child already emits for itself and per-event aggregation happens collector-side. Folding a child's contribution into its parent, or emitting once per iteration of an internal chunked loop, would over-count. The sub-solvers and devices such a loop drives own no dynamic model and never call an emit hook, so iteration alone never inflates the event count. This is the central correctness invariant of the side channel.
- **A duration is answered by arithmetic.** `latency__ns` reads its arguments and the module's own config, allocates nothing and executes no forward, so it is callable outside a profiler context and outside a measured run. The one runtime quantity it may need is the input shape a unit receives.

### Public API

- `NeuroxProfiler(*, leading_rank=0)` — the sole layout knob. It states how many leading dims the caller owns (`0` when the measured call has none, which reduces every payload to a scalar), is exposed read-only as `leading_rank`, and is applied by the collector to every energy payload. A negative value is rejected at construction.
- `total_dynamic_energy__fJ` — scalar sum over all `EnergyEvent`, resolved by finalization at context exit, so reading it is a pure CPU field read. It sums every event over every axis it kept and is therefore the whole measurement's total.
- `energy_by_type` — grouped sum (`dict[str, float]`) keyed by the emitter's class name, over the per-event scalars finalization already synced. It needs no root: `module_type` is intrinsic to the emitter.
- `energy_events: list[EnergyEvent]` — the resolved per-call event list, populated by finalization. Each event carries the emitting `module`, permitting identity-based selection without a module name. `EnergyEvent.dynamic_energy__fJ` is the reduced payload at `[*caller_leading]` — a 0-dim scalar when the caller declared no leading dims. `EnergyEvent.channel` carries the optional sub-branch label passed to the emission hook (`None` for an un-channelled event); `report(model).energy_by_name` folds it into the row name as `"<module dotted name>.<channel>"`.
- `analyze_static(model) -> StaticMetrics` — static-only staticmethod; aggregates the reporting-host walk to totals. `StaticMetrics` carries area + leakage only (`area__um2`, `leakage_power__uW`), no dynamic quantity.
- `collect_static(model) -> list[StaticRecord]` — static-only staticmethod; the per-module records behind `analyze_static`. Each `StaticRecord` carries `qualified_name`, `module_type`, `area__um2`, `leakage_power__uW`. The walk names each host as it reaches it, so the name is resolved on the spot.
- `report(model) -> ProfilerReport` — bundles this context's runtime events with a fresh static walk of `model`; must be called after the block exits. `ProfilerReport` exposes `total_dynamic_energy__fJ` over its event list, the per-name grouped sum `energy_by_name`, and `name_of(module)`. It carries `energy_scalars__fJ`, the per-event scalar totals positionally aligned with `energy_events`: `report` hands over the list finalization already synced, and a report built without one computes it on first read and caches it, so every scalar view costs at most one host sync for the report's life. `analyze_model(model)` is the static-only sibling (a report with no runtime events).
- `summary(*, static=None, extras=None) -> str` — concise multi-line text dump of the dynamic total; `static` appends area and leakage power. Neither a duration nor a static energy is derived: a duration is asked of a module family through that family's own signature, and the window leakage integrates over is a duty-cycle property a scheme declares in its own config.
- `neurox_roots(model) -> list[ModuleBase]` — the outermost NeuroX modules of a tree, found by walking and stopping the descent at the first one, so a root covers its own NeuroX children instead of listing them beside it. A model that is itself a NeuroX module is the single root; a plain container or a third-party wrapper may hold several. Placement is read from the assembled tree rather than declared at construction, because a tree is re-parented after assembly and a construction-time flag would go stale silently. A caller that wants a whole tree's duration narrows the roots to the family it is asking — a temporary stand-in for an interface that spans the families.

## Performance & resources

Per emission: one reduction down to `[*caller_leading]` (a kernel launch, no host sync) plus a Python append of the emitter reference; an expanded-constant payload reduces over stride-0 axes, so it reads one element and allocates only `[*caller_leading]`. Finalization sums each event to a scalar and does one batched device→host transfer — a single host sync, independent of event count. Static collection is one module-tree walk per `collect_static` / `analyze_static` call with $O(\mathrm{circuits})$ derived-property reads, no allocation of node-level tensors; `report` adds one more such walk to build its name map. A duration query is Python arithmetic over the module's own config, with no device work at all.

## Gotchas

- **Do not read totals mid-`with`.** The pending lists hold device tensors that have not been drained; the aggregation accessors still read their entry-reset zeros. The values are not "partial" — they are stale.
- **An exception suppresses finalization.** If the `with` body raises, no sync runs and the event lists stay empty by design. Do not rely on profiler state after a failed run.

## Known limitations

- **No tensor-return profiling path.**
- **No CSV / JSON export, no benchmark suite.** Report consumption is in-process (`ProfilerReport`, `summary`) only.
- **No per-instance energy resolution.** An event tensor resolves the caller's unit operations and nothing finer: the fabrication-instance block is summed like any other non-caller axis, so a report cannot say which tile of a multi-instance host spent what. Per-instance attribution requires a caller that indexes the instances itself.
- **Duration is one total, with no per-module breakdown.** A composite that does not sum its children exposes no per-child figure to report, so the only resolution available is the whole call.
- **Verification covers collection, layout, and representative accounting, not sync micro-cost.** `tests/common/test_profiler_naming.py` guards event collection, static collection, naming, grouping, and unrooted emitters; `tests/common/test_profiler_layout.py` the reduction at every rank, the expanded-constant payload, and channels; `tests/common/test_profiler_batch_invariance.py` the caller block, by feeding a model `torch.cat([x, x])` and asserting every emitter's energy doubles exactly — a size-1 stand-in for a caller extent is the one defect it names, a size-1 on a non-caller axis stays invisible to it; `tests/common/test_neurox_roots.py` the stop-at-first-NeuroX-module walk; `tests/primitive/digital/test_serial_accumulator.py` representative energy accounting. The batched-sync cost claim is a design invariant, not a regression-tested one.
