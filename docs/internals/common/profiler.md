# Profiler

The PPA side channel: `common/profiler.py` is the ledger a physical module bills its per-call dynamic energy to, and `common/tree.py` gives an assembled model's modules the names those bills carry. The emitter half is the profile mixin, and how each PPA quantity is physically computed is a per-subsystem cost model. Collection mechanics — activation, accumulation, finalization — are the [recorder](recorder.md)'s; this page holds what the energy channel adds. Duration is not collected: every module states its own, so it is asked rather than recorded.

## Design decisions

- **A tensor axis is physically a space axis or a time axis, and only that classification carries PPA meaning.** A **space** axis is spread across several fabricated instances that execute at once; a **time** axis is executed sequentially inside one instance. Software classifies the same dimension independently, as a parallel axis or a serial (Python-loop) one. The physical class is what decides whether $N$ positions cost $N$ durations or one, so it is the only one a cost model reads. Both physical classes are software-parallel here; the sole software-serial axis in the library is the solver's chunk loop, which bounds peak VRAM and describes no circuit.
- **The physical classification is declared, never inferred.** A broadcast shape, a size-1 slot and a loop trip count are software-level evidence, and none of them answers the physical question. The layer that introduces an axis is therefore the layer that states its class — in the config field that fixes its extent, and in the duration formula that counts it — while a module handed an axis from above classifies nothing. Reading a physical verdict off a runtime layout is a category error, not a shortcut.
- **A module's duration is its own to state, and covers only the time axes it introduces.** Composition is bottom-up: a composite whose own circuit model already spans its children's windows multiplies its own time axes rather than summing children, the same ownership principle `is_profile_target = False` expresses for area.
- **Duration is declared per family, not universally.** `latency__ns` is abstract on four family bases — `Iadc`, `DiffVadc`, `CimMacro` and `CimUnit` — and concrete on `CimEngine`; nothing else has the method, and `ModuleBase` declares none. Each family takes the arguments its own question needs and no more: an ADC the executed bit count, a macro the ADC resolution, a unit the input shape plus that resolution, the engine the plane count its unit computed. A shared parameter object is deliberately not used, because it would make every family carry the union of the others' questions. There is no default implementation and no universal formula: one work multiplies its bit count, another is affine in it, and a summing default would be silently wrong for any module that loops. A module that introduces no time axis of its own carries no duration method at all, so its area, leakage and duration all say the same thing.
- **Leakage power is a given circuit figure; the instance count is what is computed.** A per-instance leakage power is a design number a config declares, and nothing derives it. What a module computes is how many circuit instances its design parameters imply — a lane count from a column count and a sharing factor, say — and its leakage total follows as the declared per-instance power times that count. Area follows the same direction.
- **Dynamic energy arrives on a side channel, not in return values.** Every numerical return in NeuroX is the analog / digital result; the switching energy reaches the ledger through the emission hook instead of being threaded back through call signatures. Rationale: the hot-path tensor pipeline stays narrow and a leaf deep in a composite can attribute its own cost without every intermediate function growing a PPA out-parameter. The cost is a discoverability one — emission sites are invisible from a function's signature.
- **No active ledger means no pure energy work.** A leaf queries the demand gate before evaluating formulas used only for dynamic-energy reporting, and with no active ledger it skips those formulas entirely. When a ledger is active, collection is mandatory; the `Profiler` has no enable switch of its own.
- **Energy is collected as a tensor, not a Python float.** It is genuinely per-element — per-unit-operation, per-instance switching energy the report reduces — and staying on device until a report is taken lets the whole book share one batched device→host transfer instead of forcing a per-record `.item()` that would stall the pipeline on a GPU sync for one float.
- **The layout rule is the ledger's and executes in the emitter's frame.** `lay_out` folds every axis past the caller's leading dims and keeps those dims untouched, so a record is already `[*caller_leading]` when it is handed over and the emitter declares nothing about its own axes. Turning a per-op constant into a tensor is the emitting subclass's own arithmetic; a constant-per-element bill still costs nothing extra, because the emitter expands a 0-dim constant onto the billed layout, which holds no storage, and the reduction over its stride-0 axes allocates only `[*caller_leading]`. The constant also fixes the record dtype, since a billed layout is typically an integer code or a reduced-precision signal.
- **`leading_rank` is a property of the measurement and a reporting-resolution knob.** Only the measurement site can say how many leading dims its caller owns, so the rank is a construction argument of the ledger. Nothing physical rides on the number — summation is summation, and every scalar view reduces a record to a scalar anyway — so a rank that misjudges the caller block changes no total, only how finely the per-unit-operation view resolves. There is no runtime check on it.
- **A record carries a name, not a module.** An emitter cannot name itself: `nn.Module` records a child as a key in its parent's `_modules` dict and leaves the child object untouched, so a dotted name exists only as the prefix a traversal threads down from a root. Nor is placement fixed at construction, since a tree is re-parented after assembly — a probe swapped in for the block it stands in for, a plain layer replaced by its quantized twin — so the earliest a name is knowable is after assembly. Identity in the book is therefore plain text: which tree answered is settled before the measurement, and a record outlives the module it names without holding it.
- **Static collection keys on the profile-target flag.** Every module is a profile-mixin host carrying the `area__um2` / `leakage__uW` surface, so being a host does not imply owning reportable silicon: the static walk keys on `is_profile_target` and reads the two properties from the hosts that declare it true. That selects exactly the modules accounting for themselves — a composite reports only its own overhead while its children self-report — and a host the walk skips is also barred from emitting a dynamic record of its own, so nothing is double-counted.
- **A composite billing more than one branch per op names them with a `channel`, not separate emitters.** The emission hook takes an optional `channel: str | None`, and a channel is a virtual submodule: a branch its parent bills without a module instance of its own. This lets one physical module bill several independent branches without inventing a child module purely to carry a name, and it costs the emitter nothing but the string it passes.

## Names and roots

`common/tree.py` holds the two walks a report needs, and a plain forward needs neither.

- **Stamping is one post-assembly walk, and the canonical order is stamp, bind a `Reporter`, then run.** `stamp_names(model)` walks the assembled tree once and hands every profile-capable module the hierarchical name that walk produced; the module keeps it, and an emitted record carries it. The walk keeps duplicate paths and refuses a module instance bound at two of them: a physical module has one place in the hardware, so a tied or shared instance is a modelling error rather than a naming ambiguity to resolve. Binding the reporter next re-walks the same tree and rejects a missing or stale stamp there, so the whole naming question is settled before the measurement rather than at the report.
- **Stamping again overwrites.** A second call — on the same root or another one — replaces the stamps outright, so a model rewired after its first stamping is re-named by stamping it again and nothing has to be cleared first. The stamp that counts is the one the tree being reported agrees with; nothing else reads it.
- **`neurox_roots` collects the outermost NeuroX modules.** The walk stops descending at the first `ModuleBase` it meets, so a root covers its own NeuroX children instead of listing them beside it: a model that is itself a NeuroX module is the single root, while a plain container or a third-party wrapper may hold several, in child order. Roots are deduplicated by identity, so a module bound under two parents is returned once — a consumer summing over roots would otherwise count its hardware twice.

## Contracts & invariants

- **The emit-once contract.** Each logical operation emits at most one energy record per channel, and a composite emits only its own per-op overhead, never a sum of its children's, because every child already emits for itself and aggregation happens report-side. Folding a child's contribution into its parent, or emitting once per iteration of an internal chunked loop, would over-count; the sub-solvers and devices such a loop drives own no dynamic model and never call the emit hook, so iteration alone never inflates the record count. This is the central correctness invariant of the side channel.
- **A non-target must not emit.** A module the static walk skips raises if it bills dynamic energy, so the ownership decision holds on both halves of the report.
- **Record inside the context, report after it.** A report reduces whatever the book holds, and a clean exit is what parks the records on the ledger's device.
- **A duration is answered by arithmetic.** `latency__ns` reads its arguments and the module's own config, allocates nothing and executes no forward, so it is callable outside a measured run. The one runtime quantity it may need is the input shape a unit receives.
- **A whole tree's duration is asked of its roots.** A root already covers its own NeuroX children, so the roots `neurox_roots` returns are the whole tree's duration surface; a caller narrows them to the family it is asking, since duration is declared per family.

## Performance & resources

Per emission: one reduction down to `[*caller_leading]` — a kernel launch, no host sync — plus the recorder's hand-over; an expanded-constant record reduces over stride-0 axes, so it reads one element and allocates only the caller block. Records stay on device until something reduces them, so nothing on the emission path pays a sync; a book parked on the host has instead paid one transfer per record at context exit, which is what a ledger constructed with `device=None` avoids for a consumer that reduces later. Stamping is one module-tree walk with no device work, and a duration query is Python arithmetic over the module's own config.

## Gotchas

- **A size-1 stand-in for a caller extent silently under-counts.** The layout keeps the caller's leading dims and expands nothing, so an emitter that bills a real batch axis at extent one is summed as the single unit operation it claims to be.
- **An exception suppresses the parking sweep.** The book survives a failed run and stays readable, but its records sit on the device they were recorded on.
- **A rewired model needs a fresh stamping.** Names come from a walk, so surgery after stamping leaves stale ones; the reporter's construction walk is where that is caught, not the report call.

## Known limitations

- **No tensor-return profiling path.**
- **No CSV / JSON export, no benchmark suite.** Report consumption is in-process only.
- **No per-instance energy resolution.** A record's tensor resolves the caller's unit operations and nothing finer: the fabrication-instance block is summed like any other non-caller axis, so a report cannot say which tile of a multi-instance host spent what. Per-instance attribution requires a caller that indexes the instances itself.
- **Duration is one total, with no per-module breakdown.** A composite that does not sum its children exposes no per-child figure to report, so the only resolution available is the whole call.
- **Verification covers collection, layout, naming and representative accounting, not sync micro-cost.** `tests/common/test_profiler_layout.py` guards the reduction at every rank, the expanded-constant record, and channels; `tests/common/test_profiler_naming.py` that a record carries a stamped name and never a module; `tests/common/test_tree.py` the stamping and root walks; `tests/common/test_profiler_batch_invariance.py` the caller block, by feeding a model `torch.cat([x, x])` and asserting every emitter's energy doubles exactly — a size-1 stand-in for a caller extent is the one defect it names, a size-1 on a non-caller axis stays invisible to it; `tests/primitive/digital/test_serial_accumulator.py` representative energy accounting. The sync-cost claims are design invariants, not regression-tested ones.
