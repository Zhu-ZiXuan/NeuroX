# CimMacro base

`CimMacro` defines the primitive program/read, value-domain, and output-rescale surface shared by the family.

## Design decisions

- **Family dispatch keyed on config and policy types.** `(type(config), type(policy))` is the discriminator, so adding a member registers one concrete pair and never changes `from_config`; mismatched config-policy wiring fails before leaf construction.
- **Canonical windows are validated, never canonicalized.** `validate_quantization_input_range` admits exactly two inclusive shapes, unsigned `[0, upper]` and mid-zero `[-m, m - 1]`. These are the only shapes that keep the zero point on a bin edge at every bit width, so the window zero code is always computed from the shape and never configured; a symmetric `[-n, n]` window is rejected rather than widened.
- **The rescale currency is the ideal macro's output code.** `rescale_factor` expresses one macro code in ideal-macro codes, which makes the ideal member's max-bits factor the identity `1.0` — an anchor, never a stored config value. One bit-width law holds family-wide, `r_b = r_B * 2^(B - b)` with `B = adc_max_bits`, since dropping a bit doubles what one code carries; a subclass supplies `r_B` alone through `_max_bits_rescale_factor`, a config lookup for a member whose factor is a calibration artifact. Dequantization into MAC units belongs to the algorithm side, so the family exports codes plus this factor and nothing else.

## Contracts & invariants

- **Logical shape contract.** `from_config` passes owner-selected `input_num` and `output_num` to the concrete constructor. `program(w)` then takes `(*inst_shape, input_num, output_num)`; `vec_mat_mul(x)` takes primitive trailing `[input_num]` and returns primitive trailing `[output_num]`. Every leading axis of `x` is anonymous broadcast batch. The macro owns all logical-to-physical encoding and layout conversion.
- **Geometry belongs to the instance, not the config.** `CimMacroConfig` contains no dimensions. A physical member binds the constructor's logical dimensions to its own physical terminology immediately, such as `row_num = input_num` and `col_num = output_num`, and uses only that physical terminology afterward. The ideal member retains `input_num` and `output_num` because it has no physical row/column model. The abstract family deliberately exposes neither pair after construction.
- **Selection limit.** The base config requires a positive `max_active_num` and imposes no divisibility requirement. A concrete member validates the limit against its own logical-to-physical mapping. The caller masks unselected positions to zero. Selection is scheduling metadata and is independent of the runtime value at a selected position.
- **`_split_col_lanes(t, *, col_per_lane)` splits the trailing column axis into `(lane_num, col_per_lane)`.** The lane axis aligns with fabricated instance axes (parallel circuit copies) and the trailing axis is time-serial on each lane, with `lane = col // col_per_lane`; non-divisible extents raise `ValueError` — no clamping. Serial-vs-parallel semantics live in tensor shape: axes matching a stage's fabricated `inst_shape` are parallel circuit copies, every other axis is time-serial on that hardware.
- **Abstract value-domain and quantization surface.** Each subclass implements the logical value-domain properties (`x_value_range`, `w_value_range`) and the quantization surface — `quantization_input_ranges`, `adc_max_bits`, `_max_bits_rescale_factor`, `map_quantization_input_code` — while `rescale_factor` is concrete in the base. Internal digit geometry is deliberately absent from the base API.
- **The quantization mode belongs to the macro.** `quantization_input_ranges` publishes one canonical MAC-unit conversion window per mode; the tuple position is the `quantization_mode` index and the tuple length is the mode count, so the family carries no separate mode-count property. The macro only NAMES the mode, to its reference source, which selects and returns those taps; the macro therefore knows no bank layout, and no operating-mode object ever reaches the ADC primitive, which sees only an analog input, the references, and a resolution. Mode is consumed on the macro-to-reference edge and never appears on the macro-to-ADC edge.
- **`map_quantization_input_code` names the axis a member's converter discriminates on**, returning the mapped codes and their inclusive range. Two module-level free functions realize the two shapes — `map_magnitude_input_code` for a sign-magnitude readout, `map_zero_point_input_code` for an offset readout — and both validate the window first. The range a member publishes is the `adc_input_code_range` its config declares, so the calibration artifact and the axis the tools fit on are the same object; the range a free function derives from the window is deliberately discarded.
- **`adc_bits is None` is the lossless oracle.** It lies outside the `[1, adc_max_bits]` bound and outside the bit-width chain, so `rescale_factor` returns `1.0` for it without reaching the member hook — and therefore without validating the mode, which only a converting width resolves. A member with no exact path rejects it.
- **`CimMacroMode` is the config record of one physical operating point.** It carries the canonical window, the inclusive ADC input code range the mode's converter discriminates, and the max-bits rescale factor. The code range is a calibration artifact taken from circuit knowledge, not recomputed from the window.
- **One max-bits ladder serves every bit width, and bit width is ADC-internal.** The macro's only reference duty is naming the mode; it hands the converter whatever references that converter's circuit takes, unchanged by `b`, and the converter realizes `b` by running fewer decision cycles over them. A deterministic converter's raw code at `b` is therefore its full-ladder raw code right-shifted by `B - b`. There are no per-bits analog operating points, and bit width never changes sign recovery or zero-point semantics.
- **`to_ideal()` preserves the instance geometry and family contract.** The base stores the constructor's logical dimensions privately as one shape tuple and builds the ideal counterpart from the shared config fields plus the published value domains, windows, and `adc_max_bits`. A member whose encoding resolves a wider signed code range than its converter bit width overrides the published width alone; nothing else is repeated per member.
- **Ownership.** Fabricated state lives in the device children; the tile owns no static mismatch, so `_sample_fabricate_mismatch` is an explicit base no-op and the cascade fans into the children.
