# CimMacro base

The crossbar family: the abstract `CimMacro` (`base.py`) and the lossless `IdealCimMacro` (`ideal.py`). The pure array is under [array/](../../xbar/README.md); concrete scheme xbars live in their own per-scheme packages.

## Design decisions

- **Family dispatch keyed on config type, not an `isinstance` ladder.** `type(config)` is the discriminator, so adding a concrete xbar only adds a `@CimMacro.register_key(...)` line and never touches `from_config`. The cost — a config class per impl — is paid once.

## Contracts & invariants

- **Primitive shape contract.** `program(w)` takes `(*inst_shape, col_num, w_digit_count, row_num)`; `vec_mat_mul(x)` takes trailing `[row_num]` and returns per-phase codes with trailing `[active_phase_num, col_num]` (col innermost, active-phase axis immediately left). The phase axis is **always present** — size 1 when `active_row_num == row_num`; accumulation over it is the caller's (unit's) digital-domain decision, never the macro's. A caller's leading dims express **external batch and inst alignment only** — per-column / per-digit / per-phys_col fanout is an internal axis the implementation opens itself (`unsqueeze(-2)`). Encoding a column/digit position in `x`'s leading dims is a contract violation. The caller must also insert an explicit size-1 inst slot in `x` for the Cartesian `x_batch × inst` broadcast, even when `x_batch` coincidentally equals an inst dim `K`: omit that slot and PyTorch silently broadcasts the position as a *matched* axis ("one x per inst") instead of the intended Cartesian product, raising no error while the output shape and the physical workload diverge.
- **`active_row_num` is a required config field with divisibility guards.** `CimMacroConfig.validate_geometry` enforces `1 <= active_row_num <= row_num` and `row_num % active_row_num == 0` (uniform phases — every phase has the same dot-product dynamic range); the derived property `active_phase_num` returns `row_num // active_row_num`.
- **`_active_row_mask` is a non-persistent bool buffer** of shape `[active_phase_num, row_num]`; phase `p` owns rows `[p * active_row_num, (p + 1) * active_row_num)`. `_unroll_row_phase(x)` expands trailing `[row_num]` to `[active_phase_num, *span, row_num]` via `torch.where` against the mask — the active-phase axis inserts immediately LEFT of the inst-alignment span, where `*span` is `len(inst_shape)` axes (`x`'s own alignment axes, or size-1 slots when `x` omits them), so downstream right-alignment against per-instance tensors keeps the phase axis broadcast-leading and it can never collide with an inst axis; with an empty `inst_shape` the result trails `[active_phase_num, row_num]`. Zero entries hold a row's word line at its off level (the unselected-row physical state), so each phase's solve sees the full fabricated array with only its own rows driven; dtype and device follow `x`.
- **`_split_col_lanes(t, *, col_per_lane)` splits the trailing column axis into `(lane_num, col_per_lane)`.** The lane axis aligns with fabricated instance axes (parallel circuit copies) and the trailing axis is time-serial on each lane, with `lane = col // col_per_lane`; non-divisible extents raise `ValueError` — no clamping. Serial-vs-parallel semantics live in tensor shape: axes matching a stage's fabricated `inst_shape` are parallel circuit copies, every other axis is time-serial on that hardware.
- **Abstract value-domain and ADC surface.** Each subclass implements the value-domain properties (`x_range`, `w_digit_count`, `w_digit_radix`, `w_digit_range`) and the ADC operating-point surface (`adc_mode_num`, `adc_max_bits`, `adc_rescale_factor`). `adc_rescale_factor(adc_operation_point)` returns the code-to-dot-product rescale keyed on the `(adc_mode, adc_bits)` pair, and raises `KeyError` for an uncalibrated operating point.
- **`to_ideal()` carries `CimMacroConfig` fields only** — never a physical subclass's calibration table, which lives on the physical config; the ideal twin must derive its rescale from geometry alone.
- **`IdealCimMacro` is also directly config-dispatchable** (it registers its own config key) — a convenience for flow bring-up and standalone tests. A directly built twin is hand-parameterised, bound to no fabricated device, and uncalibrated, so it is a synthetic reference only; production accuracy / PPA must use a twin from `to_ideal()` on a physical config.
- **`IdealCimMacro` output-quantization contract.** `vec_mat_mul` consumes only `adc_operation_point.adc_bits`; `adc_mode` is opaque and never read. Each active phase's partial dot is quantized independently (per-phase quantize-then-accumulate: `Q(sum) != sum(Q)` in general), with the rescale range `_max_phase_dot_abs = active_row_num * max|w_logical| * max|x|` — one ADC conversion digitizes one phase. `adc_bits == 0` is the lossless sentinel — the integer per-phase partial dots are returned unmodified, with ADC quantization and the signed clamp both bypassed; their sum over the phase axis equals the lossless full dot. `adc_bits == 1` is unsupported — absent from the rescale table, so `adc_rescale_factor` raises a natural `KeyError` at that width. At `adc_bits >= 2` the quantizer follows `self.training`: under `train()` `stochastic_floor_to_int` adds a per-element `u ~ U[0, 1)` in code space before the floor (unbiased stochastic rounding for QAT), while `eval()` is the plain deterministic floor; both take the signed clamp `[-2^(adc_bits-1), 2^(adc_bits-1) - 1]`.
- **`IdealCimMacro` dot arithmetic is exact on both paths.** The per-phase dot bound `_max_phase_dot_abs` sizes the arithmetic at `__init__`: below `2^24` the row contraction runs as an fp32 einsum — every per-cell product and partial sum stays exactly representable in IEEE fp32 (framework-default matmul precision, TF32 disabled) and the cast back to `int64` is lossless — the path that keeps the tile matmul GPU-capable, since CUDA has no integer-matmul kernel. At or above the bound the int64 elementwise multiply-reduce path is kept, exact at any magnitude. Fast-path exactness assumes range-conformant digits and inputs (`w_digit_range`, `x_range`); the quantizer consumes identical fp32 per-phase dots either way, so codes are byte-identical across paths.
- **Ownership.** Fabricated state lives in the device children; the tile owns no static mismatch, so `_sample_fabricate_mismatch` is an explicit base no-op and the cascade fans into the children.
