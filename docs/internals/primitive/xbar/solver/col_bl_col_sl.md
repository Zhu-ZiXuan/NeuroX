# Parallel BL/SL DC solver

`ColBlColSlSolver` is the concrete solve of the parallel BL/SL topology — each column's cells share one BL and one SL, and columns do not interact, which is what the family name states — carrying the `ColBlColSlDcop` result container, `ColBlColSlRecord`, and its co-located `ColBlColSlProber`. It runs on two internal layers: the batched (block-)tridiagonal linear-algebra solves and the wire-KCL / driver-current builders. The nested Newton formulation, its well-posedness, and the parallel-rail structural assumptions belong to the Reference spec; this document covers the software design and trade-offs.

## Design decisions

- **The solver is stateless and fixed to one array topology, while remaining independent of concrete cell and driver implementations.** `__init__` takes only its numerical config and binds no boundary actors. `solve_dc` receives the cell, the BL driver, and the SL driver (plus their snaps) per call; it stamps no device current, models no internal cell node, and hard-wires no concrete driver class.
- **The class is non-generic; `solve_dc` is method-generic.** The cell and driver types vary per call, not per construction, so the type parameters live on the method. `solve_dc` is generic over `(CellSnapT, CellDcopT, BLSnapT, BLDcopT, SLSnapT, SLDcopT)`: the cell types retain their `XbarCellSnap` / `XbarCellDcop` bounds, and each driver carries its own snap and dcop type under the `ClampSnap` / `ClampDcop` bounds, so a driver's extra dcop outputs survive the call unwidened. `ColBlColSlDcop` is generic over `CellDcopT`, so the return type preserves the concrete cell DCOP instead of widening it to `Any`. Method-level parameters avoid a `**kwargs` boundary signature while keeping the complete surface type-checked.
- **A solver is a plain tool class, not an `nn.Module`.** It carries no buffers and no registered state, so it stays out of the core's module tree — otherwise the fabricate cascade and `state_dict` would wrongly sweep it in. The cell holds the device state; the solver holds the method (see [cell](../cell/base.md)).
- **The owning array selects its solver explicitly.** A solver is a numerical implementation of one array topology, not a configurable physical module family. The owning array therefore constructs it directly from `ColBlColSlSolverConfig`; neither the solver nor its config participates in registry dispatch. The boundary actors remain per-call arguments of `solve_dc`, not construction-time fields.
- **The cell-grid layout is a fixed solver contract.** Cell-grid tensors use `[..., col, row]`, matching the array layout. The last axis follows the wire ladder through the rows, while the second-to-last axis indexes independent columns and their BL/SL driver pairs. The solver neither accepts an axis selector nor recursively rewrites cell snaps and DCOPs. A consuming array with another internal layout must organize its solver-boundary data into this contract because that array, not the numerical solver, owns the physical meaning of its dimensions.
- **The solver has no Policy.** Every knob is either a workload-tuned numerical constant (`ColBlColSlSolverConfig`) or a method-intrinsic safety bound (`ClassVar` on the solver); none is a per-source non-ideality toggle.
- **Decompose the solve (nested) rather than one simultaneous Newton over all unknowns.** A simultaneous Newton over every wire / clamp unknown admits rail pseudo-equilibria and can leave a uA-scale BL wire residual; the nested block-Gauss-Seidel split into well-posed sub-problems eliminates both.
- **Iteration counts come from `calibrate_solver`, not hand-tuning** (chip-parameter-free step-ratio plateau; see [calibration guide](../../../../guides/calibration/README.md)). The picker emits the raw plateau plus a fixed $+1$ outer margin; the resulting `n_outer` / `n_inner` are stored in the chip config and that is their only authoritative home. The per-cell condensation count `newton_iter_num` is calibrated separately and owned by the cell (see [cell](../cell/base.md)).
- **Method-intrinsic damping caps are `ClassVar`s, not config.** They are per-iteration $|\Delta u|$ damping bounds (a Newton heuristic, not a chip parameter), so they never enter the calibrated config or any Policy. `ColBlColSlSolver` carries an outer cap `MAX_OUTER_STEP__V` (applied to the coupled $2\times2$ clamp step) and an inner cap `MAX_INNER_STEP__V` (applied to the block-$2\times2$ wire step).
- **Shared wire-ladder builders, solver-specific assembly.** `f_kcl__uA`, `g_self__uS`, and `i_drive__uA` are the single source for wire-ladder KCL, per-node self-conductance, and boundary current. Each returns exactly one physical quantity, so each is named like the variable that would hold it (see [notation_conventions](../../../../conventions/notation_conventions.md)). Sharing them keeps residuals and Jacobian diagonals numerically identical across every solver that builds the same wire ladder, rather than each solver re-deriving the stamping. Each takes the wire axis as a `dim` argument rather than carrying one function per orientation, so a rail along any axis reaches the same stamping. Assembling those per-node conductances into *this* topology's coupled BL/SL block Jacobian is not reusable vocabulary, so it stays a private static method of the solver (`_g_diag_blocks__uS`) beside the two Newton steps that consume it; the two step builders return a voltage PAIR, so they keep a bare name and suffix their elements at the unpack.
- **Numerical solves accumulate into lists, never in-place.** Both Thomas sweeps (`solve_tridiagonal`) and the block-Thomas sweeps (`solve_block_tridiagonal` and its uniform $2\times2$ specialization) accumulate intermediate results to stay compile-friendly. In-place tensor writes break `torch.compile` graph tracing; pure-functional accumulation lets inductor fuse the per-step elementwise ops across the unrolled loop.
- **Fixed shape convention for the block solver (no `dim` arg).** `solve_block_tridiagonal` fixes the $N$ axis as third-to-last for the block tensors (`[..., N, B, B]`) and second-to-last for the RHS (`[..., N, B]`); callers transpose at the call site if their layout differs. The scalar `solve_tridiagonal` instead takes an explicit `dim` because its slices are rank-uniform with the RHS and an axis argument costs nothing.
- **One block solve per step, not two.** The block forward sweep stacks the super-diagonal block and the RHS column into a single right-hand side and issues one block solve per row instead of two, then splits the result back into the coupling factor $C_k$ and the reduced RHS $d_k$.
- **Closed-form $2 \times 2$ block algebra.** Every block product and block solve in the Thomas path routes through `block_matmul` / `block_solve`, which expand $B = 2$ into elementwise multiply-adds (adjugate/determinant form for the solve) and fall through to `@` / `torch.linalg.solve` for any other $B$. Batched GEMM / batched-LU kernels on tens of millions of $2 \times 2$ blocks cost orders of magnitude more per launch than the arithmetic they perform, and the elementwise form additionally fuses under `torch.compile`; the closed form matches LU to fp round-off in the diagonally-dominant wire-Jacobian regime.
- **A uniform rail lattice gets its own block solver.** Both wire-Newton consumers face the same structure: every sub- and super-diagonal block of the coupled Jacobian is the constant $\operatorname{diag}(-G^{\mathrm{BL}}_{\mathrm{seg}}, -G^{\mathrm{SL}}_{\mathrm{seg}})$. `solve_block_tridiagonal_2x2_uniform(diag, rhs, *, off_block)` takes that pair as two Python floats and exploits $(U M U)_{ij} = u_i\,m_{ij}\,u_j$ for diagonal $U$: the forward sweep needs the four cross weights $u_i u_j$ and no block product at all, so no off-diagonal tensor is ever built and each row costs one explicit $2\times2$ inverse plus multiply-adds. The general `solve_block_tridiagonal` remains for callers whose off-diagonal blocks genuinely vary per row.

### Nested solver structure

The nested formulation is the Reference spec; the code realizes it in three phases. A **warm start** seeds the IR-drop wire voltages and the two boundary clamps. An **outer loop** of `n_outer` steps then runs clamp-first: each step takes one outer clamp-Newton step against the driver transfer law, then `n_inner` inner wire-Newton steps at the updated clamps, so the loop exits with the wire state already converged for the latest clamp and needs no post-loop consistency step. Every inner step calls `cell.solve_branch(v_bl__V, v_sl__V, cell_snap)` for the branch current and signed conductances the block-$2\times2$ wire Jacobian is assembled from; the coupled block handles a variable-SL clamp through the same code path, with no special case. Both Newtons are damped by per-iteration $|\Delta u|$ caps. An **exit refresh** calls `cell.solve_dc` to re-align the returned cell DCOP and internal node with the final wire voltages, which the last inner step leaves stale.

The solve carries two kinds of scalar — calibrated iteration counts (`ColBlColSlSolverConfig`, loaded from the chip config) and method-intrinsic damping caps (`ClassVar`s on the solver):

| Knob | Kind | Role |
|---|---|---|
| `n_outer` | config count | coupled outer Newton steps on $(V_{\mathrm{BL,CL}}, V_{\mathrm{SL,CL}})$ |
| `n_inner` | config count | inner block-Newton steps on the wire system per outer step |
| `MAX_OUTER_STEP__V` | ClassVar cap | outer-step $\lvert\Delta u\rvert$ damping cap |
| `MAX_INNER_STEP__V` | ClassVar cap | inner-step $\lvert\Delta u\rvert$ damping cap |

### Trajectory probing

`ColBlColSlProber` collects a solve's whole iteration trajectory, not just where it landed. The design follows from what the probe is for: calibration and convergence diagnosis need the residual of every iterate the solve passed through, and none of them can be recovered from a converged point.

- **Emission is a compile-time specialization, not a runtime branch.** `solve_dc` reads `ColBlColSlProber.active()` once in the eager wrapper and passes the answer into the compiled leaf as a plain `bool` parameter. Dynamo guards on it, so an active prober compiles a second graph in which the `submit` sites graph-break — correct and slower — while the unprobed graph stays break-free and is the one production runs. Reading the slot inside the leaf instead would either bake "inactive" into the trace as a constant or break the graph on every call.
- **A trajectory record carries residuals, not the state behind them.** The residual is the diagnostic; the iterate is only the thing it was evaluated at, and a consumer that reads residuals off the stream never needs the node voltages, branch currents, derivatives, clamp boundaries or port currents that produced them. Emitting the residual alone keeps a probed solve's retained memory to two node grids per inner step and one per-column pair per clamp event, rather than the whole working state of every iterate.
- **Emitted values are already computed; probing adds no physics.** Each emit site hands over residuals the iteration built anyway — the outer clamp residual pair of a clamp event, the wire KCL residual pair of an inner step. Nothing is re-evaluated for the record, so the cost of probing is the hand-over and the graph break, never a second solve.
- **A record's residuals are its own iterate's.** Every emit site fires BEFORE the step it is describing, so a record's residuals are the residuals AT that record's own iterate rather than at its successor's. That off-by-one is the whole point: a residual read against the state that produced it is what makes the trajectory readable, and it is why the terminal record — the state the final step produced — carries no residual at all.
- **The terminal record carries the converged DCOP.** It is the solve's own result, kept on the stream because the calibration tool measures step deltas between adjacent candidates on it and takes the denominators of its relative guards from it. Residuals are never recomputed from it; the trajectory's own emitted residuals are what the guard reads.
- **One record type, `(outer, inner)` selecting the residual pair.** A clamp event, an inner step, and the terminal point carry disjoint quantities, but they are one stream in one order, so they are one type with optional pairs rather than three types a consumer would have to merge. `inner == 0` is the clamp event of outer step `outer`, `inner >= 1` the inner step within it, and `outer == n_outer` the terminal record. A non-terminal record's `outer` is always `< n_outer`, so the terminal coordinate is unambiguous without a discriminating flag.
- **Filtering is collection-side, through `min_outer`.** The emitter stays blind to who is listening — it emits the whole trajectory whenever `record` is true — and `ColBlColSlProber(min_outer=...)` turns away everything below its threshold on arrival, by overriding `RecorderBase.submit` — gate first, then hand the survivors to `_submit_record` — with the `@torch.compiler.disable` every reader of the active slot owes. Gating at the emit site instead would push a recorder's policy into the compiled leaf and specialize the graph on it; gating at exit instead would hold the whole trajectory in memory first, which is exactly what `min_outer` exists to avoid. Because the terminal record sits at `outer == n_outer`, it survives every legal threshold, so a consumer that wants converged points alone sets `min_outer` to the outer count.
- **`min_outer` is required, with no default.** The trajectory of a long solve is large and grid-shaped, so how much of it to keep is a decision the caller must make rather than one a default can make for them.

## Contracts & invariants

- **`@torch.compile` constraints (compiled leaf).** `solve_dc` is a thin eager wrapper; the compiled unit is the inner `_solve_dc_impl` leaf carrying the entire warm-start / outer / inner / exit-refresh solve. That leaf obeys: no in-place tensor writes; no Python-side branches on tensor values; no autograd reads of attributes that change across calls. Respecting them yields a single fused kernel over the solve, including the numerical solves it calls; the probe gate is a `bool` parameter the leaf specializes on rather than a tensor-valued branch, and the slot read that produced it sits in the eager wrapper, outside every graph.
- **The trajectory is submitted to a co-located recorder, never returned.** `solve_dc` returns only the converged `ColBlColSlDcop`. Every diagnostic leaves through `ColBlColSlProber.submit(...)`, gated on the `record` flag so an unprobed solve builds no record at all, and the record objects are constructed inside the gate rather than before it. Because nothing on the emit path feeds back into the iteration, the returned DCOP is bit-identical probed vs unprobed — under compile as well as eagerly, the two specializations differing only in what they hand out. Per-cell residuals remain inside the cell interface and are neither read nor forwarded.
- **Record coordinates.** A trajectory record carries `(outer, inner)` and exactly one residual pair: `inner == 0` fills the outer clamp residuals `f_bl_clamp__V` / `f_sl_clamp__V`, `inner >= 1` the wire KCL residuals `f_bl_kcl__uA` / `f_sl_kcl__uA`. The terminal record at `outer == n_outer` carries `dcop` and nothing else. Every field a record's kind does not fill is `None`, and a consumer reads the kind off `(outer, inner)` rather than probing for presence.
- **Wire-ladder layout for the shared builders.** `f_kcl__uA`, `g_self__uS`, and `i_drive__uA` take the wire axis as `dim` and assume the driver hangs off index 0 of it through one link. `dim` must be NEGATIVE: in `f_kcl__uA` the trailing-pad width that drops the open end's absent link is derived from it as `(0, 0) * (-dim - 1) + (0, 1)`, which is exact for a negative index alone. This solver passes its module-level `_WIRE_DIM` (`-1`), the row axis of its `[..., col, row]` cell grid. `segment_g__uS` is the scalar conductance of one lattice link, shared by every link of that rail including the driver's: index 0 is not distinguished, and the one distinguished node is the ladder's open end at the far index, which has no link onward.
- **The cell is the only device interface; the drivers are the only boundary interface.** A solve reads device behaviour exclusively through the cell's condensed-branch surface (`cell.solve_branch`, `cell.solve_dc`) and boundary behaviour through each driver's `solve_dc`, reading `v_clamp__V` and `dvclamp_di__MOhm` off the returned dcop and passing the snaps it received. It consumes the cell's condensed-branch and signed-conductance contract unchecked, so a cell that violates the signs silently corrupts the solve rather than raising.
- **`ColBlColSlDcop` is the complete solve result.** It carries the wire and clamp state plus the condensed cell DCOP (`ColBlColSlDcop.cell`) behind one solver-independent data contract.
- **The rail lattice reaches the solve as two scalars.** `solve_dc` declares `bl_segment_r__MOhm` and `sl_segment_r__MOhm` as plain Python floats and derives the link conductance $1/r$ at entry, uS being exactly the reciprocal of MOhm. Nothing below that entry holds a per-row profile, so a rail whose links differ node by node is outside this interface rather than a value it can carry.
- **Degenerate extents are not guarded.** A single row, a single column, and a single block row are all well-defined systems the same code path settles, so nothing rejects them. Only checks that prevent silent corruption survive anywhere in this package — the chunking layer's leading-shape check and each algorithm's own shape assumptions; a one-position axis is not a corruption and a `> 1` precondition would only have blocked the smallest useful test case.
- **Sign / unit conventions.** The KCL residual is returned in uA with the convention $r = i_{\mathrm{inject}} + \Delta v_{\mathrm{left}} \cdot g_{\mathrm{seg}} + \Delta v_{\mathrm{right}} \cdot g_{\mathrm{seg}}$, where $\Delta v_{\mathrm{left}}[k] = v[k] - v[k-1]$ (and $v[0] - v_{\mathrm{drive}}$ at the driver end) and $\Delta v_{\mathrm{right}}[k] = v[k] - v[k+1]$ (zero at the far end, which has no link onward). Node voltages are V, the segment conductance uS, currents uA.
- **Boundary slots are ignored, not validated.** In `solve_tridiagonal` the `sub` entry at index 0 and the `sup` entry at the last index are unused boundary slots; in `solve_block_tridiagonal` the `sub` block at $k=0$ and the `sup` block at $k=N-1$ are unused. The algorithms never read them — callers need not zero them.
- **Block-count semantics ($B$).** `solve_block_tridiagonal` works for any block size $B$ from the same code path: $B=1$ reduces to scalar Thomas and matches `solve_tridiagonal` numerically up to fp64 round-off, and $B=2$ is the coupled two-rail wire Newton the nested solver uses; larger $B$ runs through the identical sweep for any topology that couples more node classes per row. The single-block fast path ($N=1$) is one $B \times B$ `torch.linalg.solve`, and it returns the full `[..., N, B]` rank the sweep does — a shortcut that dropped the length-one axis would be a rank change the caller cannot see coming.

## Performance & resources

- **Cell condensation sets the array memory.** Condensing the cell's internal node removes one unknown per cell from the array solve, so the wire Jacobian stays block-$2\times2$ (`[..., col, row, 2, 2]`) rather than carrying the internal node. The solver performs no leading-batch chunking.
- **Probing costs a graph break per emit and a grid-shaped residual pair per inner step.** The `record=True` specialization breaks the graph at each `submit`, so a probed solve loses the single fused kernel and runs as a chain of smaller ones; it also retains every inner step's two KCL residual grids for as long as the recorder is open. Both costs scale with `n_outer * n_inner`, which is why `min_outer` exists and why production paths run unprobed.
- **Thomas vs block-Thomas cost.** Scalar Thomas is $O(N)$ elementwise work per system; block-Thomas is $O(N \cdot B^3)$ with one $B \times B$ solve per row, so memory stays $O(N \cdot B^2)$ per leading-batch instance. The block solver carries one extra trailing rank versus the scalar solver even at $B=1$.
- **A constant off-block costs no memory.** Because the uniform block path takes the coupling as two scalars, the inner Newton and the $K$ build hold the diagonal blocks, the right-hand side, and the per-row reduced inverse and reduced RHS, and nothing grid-shaped is spent on off-diagonal blocks that are one repeated constant.
- **Unrolled-loop fusion.** Because the sweeps build Python lists and `torch.stack` once, the per-step ops are pure-functional and inductor fuses the unrolled forward and back sweeps; there is no per-iteration kernel launch in the compiled graph.
- **No materialised dense matrix.** The Thomas path never assembles the full $N B \times N B$ system, so its per-instance memory does not scale with $N^2$.

## Gotchas

- **`B=1` block-Thomas is not bit-identical to scalar Thomas.** It agrees only up to fp64 round-off because the $1 \times 1$ `torch.linalg.solve` path differs arithmetically from the scalar division in `solve_tridiagonal`; the wire Newton uses $B=2$, but use the scalar helper when exact reproducibility against the scalar path matters.
- **`solve_block_tridiagonal` has no `dim` argument by design.** Passing data in a different axis order silently mis-indexes the block sweep rather than erroring; transpose to `[..., N, B, B]` / `[..., N, B]` before calling.
- **`off_block` is the Jacobian entry, not the link conductance.** `solve_block_tridiagonal_2x2_uniform` uses the pair verbatim as the shared off-diagonal block, so the wire Newton passes the negated conductances $(-G^{\mathrm{BL}}_{\mathrm{seg}}, -G^{\mathrm{SL}}_{\mathrm{seg}})$; handing it the positive pair solves a different system silently.

## Known limitations

- **No pivoting in the Thomas sweeps.** `solve_tridiagonal`, `solve_block_tridiagonal`, and the uniform $2\times2$ specialization all assume the modified diagonal (block) stays non-singular through the forward sweep; they perform no row/block pivoting. Well-posedness is the responsibility of the Newton formulation, not these numerical solves.
- **Cell condensation is verified through residuals, not a global Jacobian.** Correctness rests on the solver's wire/clamp KCL residuals, the cell's own internal residual where applicable, and physical-vs-ideal agreement.
